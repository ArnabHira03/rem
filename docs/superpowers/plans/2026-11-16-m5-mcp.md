# M5: MCP Shim + Backlog Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any MCP client (Claude Code first) can search, list, add, confirm, update and delete rem memories and read their history through `rem mcp`. Before that, the carried-over M3/M4 backlog is cleared.

**Architecture:** `rem mcp` is a stdio JSON-RPC server (newline-delimited, MCP 2024-11-05 … 2025-11-25). Like the CLI, it is a thin client: every tool call goes through `RemClient` to the one daemon, which it auto-starts with `ensure_daemon`. It never opens a store. The protocol layer (`rem/mcp/protocol.py`) is separate from the tool layer (`rem/mcp/tools.py`), so each can be tested without the other. `rem install claude-code` also registers the server through the `claude mcp` CLI and never edits `~/.claude.json` itself. The backlog tasks come first because they touch `memory.py`, `service.py`, `spool.py` and the prompt, which the MCP tasks rely on.

**Tech Stack:** Python 3.14, stdlib `json`/`sys` for MCP (no new runtime dependency), the existing `httpx` `RemClient`, pytest.

**Spec:** `docs/superpowers/specs/2026-11-15-rem-design.md` (M5 row; rev-1 decision 10, the MCP tools; decision 7, trust) and the "Deferred" sections of `plans_completed/m3.md` and `plans_completed/m4.md`.

## Global Constraints

- Python ≥ 3.14; build with `uv_build`; **no new runtime dependency** (the MCP SDK is deliberately not used: its dependency tree would make `rem mcp` far heavier than the hook).
- `rem mcp` writes **only JSON-RPC messages** to stdout, one per line, UTF-8. Diagnostics go to stderr.
- `add_memory` from MCP always stores `provenance = assistant_generated`, `status = unverified`, `source = "mcp"`, `actor = "mcp"` (decision 7: assistant facts start unverified). Every other write tool uses `actor = "mcp"`.
- MCP tool names are exactly: `search_memory, list_memories, add_memory, confirm_memory, update_memory, delete_memory, memory_history` (decision 10).
- Clients never touch storage: the MCP server and the CLI use `RemClient` only.
- Only `Memory` writes the stores; `retrieve` never writes; the write order is Qdrant → history → done.
- Unix socket paths stay ≤ 100 bytes: tests use the `short_dir` / `daemon_env` fixtures.
- API keys come only from environment variables.
- Paid or local evals are pre-approved (`rem eval extraction`, `pytest -m llm`). The dev LLM is local Ollama `qwen3.5:4b` with `think = false`.

## Review Focus

1. **A malformed line on stdin** (not JSON, not UTF-8, a JSON array, or a non-object): reply with a JSON-RPC error (`-32700` or `-32600`, `id: null`) and keep serving. Never crash or write a traceback to stdout. Tests in Task 7.
2. **The daemon is down or still starting when a tool is called:** the tool returns `isError: true` with the daemon message, the server keeps running, and the next call tries again. Test in Task 8.
3. **Unknown notifications** (e.g. `notifications/cancelled`) and any message without an `id`: no output at all. Test in Task 7.
4. **The client's `protocolVersion` is newer than ours:** answer with our newest supported version, not an error. Test in Task 7.
5. **The process cwd is not a git repository** (e.g. `/` or `$HOME`) and the agent calls `add_memory` with `scope = "project"`: an `isError` result, and nothing is stored. Test in Task 8.

### Task 7: MCP protocol layer

**Files:**
- Create: `src/rem/mcp/__init__.py` (empty), `src/rem/mcp/protocol.py`
- Test: `tests/test_mcp_protocol.py`

**Interfaces:**
- Produces:
  - `@dataclass class Tool: name: str; description: str; input_schema: dict; handler: Callable[[dict], ToolResult]`
  - `@dataclass class ToolResult: text: str; is_error: bool = False`
  - `SUPPORTED_VERSIONS = ("2025-11-25", "2025-06-18", "2025-03-26", "2024-11-05")` (newest first)
  - `serve(tools: list[Tool], stdin: TextIO, stdout: TextIO, *, instructions: str) -> int`: reads lines until EOF and returns 0.
  - `handle(message: object, tools: dict[str, Tool], instructions: str) -> dict | None`: one parsed message → a response dict, or `None` for notifications.

Behaviour (JSON-RPC 2.0, one JSON object per line, `ensure_ascii=False`, flush after each line):

| Input | Response |
|---|---|
| `initialize` | `{"protocolVersion": <client's if in SUPPORTED_VERSIONS else SUPPORTED_VERSIONS[0]>, "capabilities": {"tools": {"listChanged": false}}, "serverInfo": {"name": "rem", "version": importlib.metadata.version("rem")}, "instructions": instructions}` |
| `ping` | `{}` |
| `tools/list` | `{"tools": [{"name", "description", "inputSchema"}]}` in registration order, no pagination |
| `tools/call` known tool | `{"content": [{"type": "text", "text": r.text}], "isError": r.is_error}`. A handler exception becomes `isError: true` with `"<ExcClass>: <msg>"`. |
| `tools/call` unknown tool | error `-32602`, message `"unknown tool: <name>"` |
| any message without `"id"` | no output |
| unknown method with id | error `-32601` |
| a line that is not valid JSON, or not valid UTF-8 | error `-32700`, `id: null` |
| JSON that is not an object (including batch arrays) | error `-32600`, `id: null` |

Requests are answered even before `initialize` (Review Focus 3).

- Produces:

Tools (JSON Schema `inputSchema`, `"additionalProperties": false`; `scope` enum = `global|system|project`, `status` enum = `verified|unverified`):

| Tool | Arguments | Calls | Text on success |
|---|---|---|---|
| `search_memory` | `query` (string, required), `limit` (int 1–50, default 10), `scope` | `search(query, cwd, limit, scope)` | `search_line` per hit, or `"No memories found."` |
| `list_memories` | `scope`, `status`, `limit` (int 1–200, default 50) | `list(scope, status)[:limit]` | `memory_line` per memory, or `"No memories found."` |
| `add_memory` | `text` (required), `scope` (default `global`) | `add(text, scope, cwd, provenance="assistant_generated", status="unverified", source="mcp", actor="mcp")` | `"Saved as unverified (the user can confirm it): " + memory_line` |
| `confirm_memory` | `id` (required) | `confirm(id, actor="mcp")` | `"Confirmed: " + memory_line` |
| `update_memory` | `id`, `text` (required) | `update(id, text, actor="mcp")` | `"Updated: " + memory_line` |
| `delete_memory` | `id` (required) | `delete(id, actor="mcp")` | `"Deleted <id>"` |
| `memory_history` | `id` (required) | `history(id)` | `history_line` per row |

`add_memory` with `scope = "project"` first checks `(project_root(cwd) / ".git").exists()` (`project_root` from Task 2). If that is false, it returns `isError` with `"project scope needs a git repository; rem mcp is running in <cwd>"` and calls nothing. The MCP server's cwd is less certain than a hook's, so it must never invent a project from `/` or `$HOME`.

Errors are returned as `ToolResult(is_error=True)`: `MemoryNotFound` → `"No memory with id <id>"`; `ValueError` (daemon `invalid`, including missing or wrong arguments checked in the handler) → its message; `DaemonUnavailable`/`RemError` → its message.

Description copy (the agent reads these):
- `confirm_memory`: "Mark a memory as confirmed true. Only call this when the user has explicitly confirmed the fact in this conversation; never to verify your own claims."
- `add_memory`: "Save a durable fact about the user, their machine, or this project. It is stored as unverified until the user confirms it."
- `INSTRUCTIONS`: "rem is the user's long-term memory shared across AI agents. Search it before asking the user about their preferences, environment, or project conventions. Save durable facts with add_memory; never save secrets."
