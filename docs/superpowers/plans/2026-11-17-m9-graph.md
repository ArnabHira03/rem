# M9 Graph Window Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `rem graph` opens a read-only, black-and-white desktop window that draws the entities, relations and memory↔entity links rem has stored, grouped visually by identical normalized name.

**Architecture:**
- The daemon gains one read-only route, `GET /graph`. It returns the raw stored records in one `StoreThread` call.
- `rem graph` fetches that snapshot over the socket. A pure-Python view builder filters and then groups it into nodes and edges.
- A pywebview window on Qt renders the view with a vendored cytoscape.js and talks to Python through `js_api`.
- There is no HTTP server, no TCP port and no storage change.

**Tech Stack:** Python 3.14, Starlette and httpx (existing), pywebview 6.2.1 with PySide6 (optional `graph` extra), cytoscape.js 3.34.4 (vendored), pytest.

**Spec:** `docs/superpowers/specs/2026-11-17-m9-graph-design.md`. Read it in full, especially "Grouping requirements" and "Builder's decisions".

## Global Constraints
- Read-only. No new collection, table, payload field or history row. Nothing in M9 calls a `Memory` write method.
- Records are grouped only when their `normalized` names are identical. Aliases, similar names and semantic similarity never group records.
- Project and scope filters are applied before grouping.
- Every edge is a stored relation or a stored memory↔entity link. A relation whose ends share a node is not drawn but is listed in the panel.
- Every original entity id, scope, project, relation and memory association is preserved in the view's `members`.
- The memory↔entity link rule: an edge from M to N exists iff some member E of N has `E.id ∈ M.entity_ids` or `M.id ∈ E.memory_ids`, and both M and E are kept. There is one edge per (M, N).
- Black and white only: white background, black and grey ink, no hue. Entity type is shown by shape (person ellipse, tool round-rectangle, project hexagon, language diamond, org rectangle, place triangle, concept octagon, mixed/other ellipse).
- Optional extra: `graph = ["pywebview[pyside6]>=6.2.1"]`. Without it, `rem graph` prints `install the graph extra: uv sync --extra graph` to stderr and exits 3.
- cytoscape.js **3.34.4**, vendored. No CDN, no network at runtime. The page is loaded with `webview.create_window(html=...)`.
- Nothing in the default `uv run pytest` suite imports `webview`, `qtpy` or `PySide6`.
- The `[graph]` extra must not be needed for any other command.

## Review Focus
1. **An empty store, or a repo rem has never seen:** the view should be empty and the window should show "rem hasn't extracted any entities here yet", not crash. `current_project_id` is `null`, so the default view is "all". (Tests: Task 1 `test_graph_snapshot_unknown_repo_has_no_current_project`, Task 2 `test_empty_snapshot_gives_empty_view`.)
2. **Memory text containing HTML or `<script>`:** it must show as literal text. The JS must never assign `innerHTML` from data. (Test: Task 3 `test_page_never_uses_innerhtml`.)
3. **A relation or link pointing at an entity or memory missing from the snapshot** (a crash window, or filtered out): it is skipped with no exception. (Test: Task 2 `test_dangling_ids_are_skipped`.)
4. **Grouped members whose types disagree** (`uv` as a tool in one repo and a concept globally): the node type is `mixed` and each member keeps its own type. (Test: Task 2 `test_mixed_types_and_members_keep_their_own`.)
5. **No display available** (SSH, a headless session) or a Qt startup error: `rem graph` prints `rem: could not open the graph window: <error>` and exits 1 with no traceback. (Test: Task 4 `test_cli_graph_window_failure_exits_1`.)

### Task 2: Pure view builder (filter → group → edges)

**Files:**
- Create: `src/rem/graph/__init__.py` (empty), `src/rem/graph/view.py`
- Test: `tests/test_graph_view.py`. Build snapshots as plain dicts with a small local `snap(entities=…, relations=…, memories=…, projects=…)` helper. No `Memory` needed.

**Interfaces:**
- Consumes: the snapshot dict from Task 1.
- Produces:
  - `build_view(snapshot: dict, *, project: int | Literal["all"], scopes: Collection[str], show_memories: bool) -> dict`, returning `{"nodes": list[dict], "edges": list[dict]}`. It never mutates `snapshot`.
  - `default_filters(snapshot: dict) -> dict`, returning `{"project": snapshot["current_project_id"] or "all", "scopes": ["global", "system", "project"], "show_memories": False}`. A `current_project_id` of `0` counts as a real id: use `is None`, not `or`.
  - Entity node: `{"id": "ent:<normalized>", "kind": "entity", "label", "type", "verified", "n_relations", "n_memories", "members", "relations", "memories"}`.
    - `label` is the first member's `name`, with members sorted by (scope, project_name or "", entity_id).
    - `type` is the common member type, else `"mixed"`.
    - Each member is `{"entity_id", "name", "type", "aliases", "scope", "project_id", "project_name", "relations", "memories"}`, holding that record's own relations and memories.
    - A relation entry is `{"id", "direction": "out"|"in", "type", "other": <other end's name>, "other_node", "status", "provenance", "scope", "project_id", "project_name", "drawn": bool}`.
    - A memory entry is `{"id", "text", "status", "provenance", "scope", "project_id", "project_name"}`.
    - Node-level `relations` and `memories` are the de-duplicated union of the members' entries (by `id`). `n_relations` and `n_memories` are their lengths.
  - Memory node (only when `show_memories` is on): `{"id": "mem:<id>", "kind": "memory", "label": text[:80], "text", "verified": status == "verified", "status", "provenance", "scope", "project_id", "project_name", "entity_nodes": [...]}`.
  - Edge: `{"id": "rel:<relation id>", "kind": "relation", "source": node id, "target": node id, "rel_type", "status", "provenance", "sentence", "evidence": len(memory_ids), "project_name"}`, or `{"id": "men:<memory id>:<normalized>", "kind": "mention", "source": "mem:<id>", "target": "ent:<normalized>"}`.
  - The order is deterministic: nodes sorted by `id`, edges sorted by `id`.

Algorithm (the spec fixes the order; follow it exactly):
1. **keep(record)**: `record["scope"] in scopes` and (`record["scope"] != "project"` or `project == "all"` or `record["project_id"] == project`). Apply it to entities, relations and memories independently.
2. **Group** kept entities by `normalized`. Use nothing else: not aliases, not names.
3. A **relation** is kept iff `keep(rel)` and both `source_entity_id` and `target_entity_id` are kept entity ids. `drawn = (source node != target node)`. Emit an edge only when drawn, but always list the relation under both end members.
4. A **link** (M, E) exists iff M and E are both kept and (`E.id in M.entity_ids` or `M.id in E.memory_ids`). A memory listed under a member, the node's `n_memories` and `verified` (any linked memory verified) all come from links only.
5. `project_name` for entities and relations comes from `snapshot["projects"]` by id (None for global/system).

### Task 3: Window page, vendored cytoscape and the `Api` bridge

**Files:**
- Create: `src/rem/graph/static/graph.html`, `graph.css`, `graph.js`
- Create: `src/rem/graph/static/vendor/cytoscape.min.js`, `vendor/LICENSE`, `vendor/README.md` (records the version 3.34.4, the source URL and the sha256)
- Create: `src/rem/graph/window.py`
- Modify: `pyproject.toml` (the `graph` extra)
- Test: `tests/test_graph_window.py` (no Qt imports)

**Interfaces:**
- Consumes: `RemClient.graph` (Task 1), `build_view` and `default_filters` (Task 2).
- Produces:
  - `render_html() -> str`: reads `graph.html` and inlines `graph.css` (in `<style>`), then `vendor/cytoscape.min.js` and `graph.js` (in `<script>`), via `importlib.resources.files("rem.graph") / "static"`.
  - `class Api`, built as `Api(client: RemClient, cwd: Path | None)`, with these methods (pywebview exposes each to JS as `window.pywebview.api.<name>`):
    - `initial() -> dict`: fetches the snapshot if none is cached and returns `{"filters": default_filters(snap), "projects": snap["projects"], "generated_at": snap["generated_at"], "view": build_view(snap, **filters)}`.
    - `view(filters: dict) -> dict`: `build_view` on the cached snapshot. It validates `filters` keys and passes `project` through as an int or `"all"`.
    - `refresh(filters: dict) -> dict`: re-fetches through `client.graph(cwd)`, then returns the same shape as `initial()` but using the given filters. If the project id in them is gone, it falls back to `"all"`.
  - `import_webview()`: does `import webview` and `import qtpy` and returns the `webview` module. It raises `ImportError` when the extra is missing.
  - `run_window(client: RemClient, cwd: Path | None) -> None`:
    - Calls `import_webview()`.
    - Then `webview.create_window("rem — graph", html=render_html(), js_api=Api(client, cwd), width=1200, height=800, background_color="#FFFFFF")`.
    - Then `webview.start(gui="qt")`. It blocks until the window closes.

**Page behaviour** (`graph.js`). Everything the spec's "Visual style" and "Interaction" sections list:
- On `pywebviewready`, call `api.initial()` and build the cytoscape graph with the `cose` layout.
- Top bar:
  - project `<select>` ("all" plus projects);
  - global/system/project checkboxes;
  - "show memories" checkbox;
  - search input;
  - ⟳ button;
  - snapshot time.
- Any filter change calls `api.view(filters)`, re-lays out, and keeps the selection if the node id still exists.
- Search is case-insensitive substring on `label` and the members' `name`/`aliases`, done in JS only. Matches get class `match`, others get `dim`. Enter centres on the first match.
- Hover shows the tooltip (`label · type`, `N relations · N memories`; a memory node shows its `label`) and dims the non-neighbourhood to opacity 0.15.
- Clicking a node or edge opens the right panel:
  - For an entity: one `<section>` per member, with name, type, scope, project and a copyable entity id, then that member's relations (with ✓/◌, the project, and "(same node)" when `drawn` is false) and memories.
  - For a memory: full text, status, provenance, scope, project, id and linked entity nodes.
  - For a relation edge: sentence, status, provenance, evidence count, project.
- Clicking a node name in the panel selects that node. Esc or ✕ closes the panel. A click on empty canvas clears the selection.
- An empty view shows the text "rem hasn't extracted any entities here yet".
- All text from data goes in through `textContent` or `document.createElement`, **never `innerHTML`**.
- Styling uses the Global Constraints shapes and B/W rules:
  - verified entity: black fill; unverified: white fill with a dashed 2px black border;
  - relation edges: verified solid black, unverified dashed grey (#888), with a triangle arrow; the label `rel_type` shows only on `:selected` or hover;
  - memory nodes: 8px grey (#666), filled if verified, hollow if not;
  - mention edges: 1px dotted #bbb;
  - `:selected`: a 4px black ring;
  - a legend in the corner.
