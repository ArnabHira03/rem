# M2 — rem Daemon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One long-running `rem daemon` owns both stores and a durable ingestion queue. The CLI, and later hooks and MCP, talk to it over a local Unix socket. It starts through systemd or on demand, stops cleanly, and recovers from crashes without losing or duplicating work.

**Architecture:**
- A Starlette app is served by uvicorn on `$XDG_RUNTIME_DIR/rem.sock`.
- Every `Memory` call runs on **one dedicated store thread**, so Qdrant local mode and the SQLite connection are only ever touched from one thread. That thread is the single writer.
- `POST /ingest` stores redacted conversation turns and upserts a debounced per-session job in SQLite.
- An async worker claims jobs with a lease and hands them to a pluggable `JobHandler`. M2 ships a no-op handler; M3 plugs in LLM extraction.
- `flock` guarantees one instance. The CLI becomes a thin client that auto-starts the daemon.

**Tech Stack:** Starlette, uvicorn (UDS), httpx (UDS transport), stdlib `fcntl`, `signal`, `subprocess`, `sqlite3`; everything from M1.

**Spec:** `docs/superpowers/specs/2026-11-15-rem-design.md`. M2 row; sections "Ingestion & queue" (rev 1 decisions carried over), "Lifecycle", "Crash-safe write ordering", and the user's daemon requirements (decision 5: centralized ingestion queue, controlled writes, session identification, duplicate prevention, defined start/stop/crash recovery).

## Global Constraints

- Socket path: config `[daemon] socket_path`, else env `REM_SOCKET`, else `$XDG_RUNTIME_DIR/rem.sock`, else `<data_dir>/rem.sock`. **The path must be ≤ 100 bytes**; longer paths raise `ValueError("socket path too long (N bytes, max 100): <path>")`. The socket is chmod `0600` right after bind.
- Lock file `<data_dir>/rem.lock`, held with `fcntl.flock(LOCK_EX | LOCK_NB)` for the daemon's lifetime; the daemon's PID is written into it. Log file: `<data_dir>/daemon.log`.
- Daemon exit codes: `0` clean stop; `2` another instance already running; `3` configuration error (embedder mismatch, bad socket path, unavailable embedder). The systemd unit uses `Restart=on-failure` and `RestartPreventExitStatus=2 3`.
- Queue settings (`[daemon]` config with these defaults): `debounce_seconds = 5`, `lease_seconds = 120`, `max_attempts = 5`, `start_timeout_seconds = 15`. Retry delay after failure n (1-based) = `min(5 * 2**(n-1), 300)` seconds.
- Ingest idempotency: `UNIQUE(session_pk, message_id)` + `INSERT OR IGNORE`. A missing `message_id` becomes `sha256(role + "\n" + content)[:32]`. Sessions are keyed `UNIQUE(source, session_id)`.
- Message contents are **redacted before storage** (see Task 3). Nothing unredacted reaches SQLite.
- **All `Memory` and `RemDB` calls go through the single store thread.** No route or worker touches them directly.
- HTTP API: JSON in and out. Errors use the body `{"error": "<code>", "message": "<text>"}`, with these codes:
  - `invalid` (400) for `ValueError`
  - `not_found` (404) for `MemoryNotFound`
  - `conflict` (409) for any other `RemError`
- The CLI keeps M1's exit codes and messages: 0 ok, 1 RemError/not found, 2 invalid input.
- Existing M1 behaviour and tests must keep passing. Only `tests/test_cli.py` changes, because the CLI now goes through the daemon.

## Review Focus

1. **The daemon is down and two CLI commands start at once.** Both may try to auto-start; exactly one daemon must win, and both commands must succeed (the loser waits for the socket). Test in Task 9.
2. **A stale socket file left by a crashed daemon.** The next start must remove it and bind, never fail with "address in use", and never delete the socket of a *running* daemon (it only deletes after acquiring the lock). Test in Task 8.
3. **The same turns ingested twice** (a hook re-sending after a timeout) must add no messages and must not create a second pending job for the session. Test in Task 4.
4. **The auto-start fails** because of a broken config or a mismatched embedder. The CLI must print the daemon's actual error (the last lines of `daemon.log`), not a generic timeout. Test in Task 9.
5. **A `SIGTERM` while a job is being handled** must let the job finish or release its lease (`status` back to `pending`) before exiting, never leaving it stuck in `processing` until the lease expires. Test in Task 7.

### Task 4: Ingestion store and job queue

**Files:**
- Create: `src/rem/storage/queue.py`, `tests/test_queue.py`

**Interfaces:**
- Consumes: `RemDB.conn` (Task 2), `redact` (Task 3), `DaemonConfig` (Task 1), `resolve_project` + `RemDB.upsert_project` (M1).
- Produces:
  - `@dataclass Turn(role: str, content: str, message_id: str | None = None, ts: str | None = None)`
  - `@dataclass Job(id: int, session_pk: int, source: str, session_id: str, project_id: int | None, attempts: int)`
  - `@dataclass IngestResult(session_pk: int, accepted: int, duplicates: int, job_id: int | None)`
  - `IngestStore(db: RemDB, settings: DaemonConfig, clock: Callable[[], float] = time.time)`:
    - `ingest(source: str, session_id: str, cwd: Path | None, turns: list[Turn]) -> IngestResult`. In one transaction:
      - upsert the session (project from `cwd` when given)
      - `INSERT OR IGNORE` the redacted turns
      - only if accepted > 0: when the session has a `pending` job, set its `not_before = now + debounce`; otherwise insert a new `pending` job with that `not_before`
      - `job_id` is that pending job's id, or `None` when nothing was accepted
    - `claim() -> Job | None`. In one `BEGIN IMMEDIATE` transaction, it picks the oldest job (by `not_before`) that is either
      - `pending` with `not_before <= now`, where its session has no `processing` job whose lease is still valid, or
      - `processing` with `lease_until < now` (an expired lease, i.e. a crashed run).

      It sets `status='processing'`, `lease_until = now + lease_seconds`, and stamps `messages.job_id = job.id` on that session's messages where `job_id IS NULL`. A reclaimed job keeps its originally stamped messages.
    - `messages_for(job_id: int) -> list[Turn]` (in insertion order)
    - `context_for(job_id: int, limit: int = 10) -> list[Turn]`: earlier messages of the same session not stamped with this job, the last `limit`
    - `complete(job_id) -> None`: status `done`
    - `fail(job_id, error: str) -> None`: `attempts += 1`, `last_error = error[:2000]`. If attempts ≥ `max_attempts` → `failed`; else `pending` with `not_before = now + min(5 * 2**(attempts-1), 300)`, `lease_until = NULL`.
    - `release(job_id) -> None`: back to `pending`, `lease_until = NULL`, attempts unchanged (used on shutdown)
    - `recover() -> int`: at startup, expired-lease `processing` jobs → `pending`; returns the count
    - `counts() -> dict[str, int]`: always has all four statuses

### Task 7: Worker loop and job handler

**Files:**
- Create: `src/rem/daemon/worker.py`, `tests/test_worker.py`

**Interfaces:**
- Consumes: `IngestStore`, `Job`, `Turn` (Task 4); `StoreThread`, `RemService` (Task 6).
- Produces:
  - `class JobHandler(Protocol)`: `async handle(job: Job, turns: list[Turn], context: list[Turn], service: RemService) -> None`. Raising means the job failed. In M3 the handler calls the LLM outside the store thread and writes through `service`.
  - `NoopHandler`: does nothing (M2 default).
  - `Worker(service: RemService, handler: JobHandler, poll_seconds: float = 0.5)`:
    - `async run(stop: asyncio.Event) -> None` loops until `stop` is set. Each iteration it:
      - claims through the store thread
      - if there's no job, waits `poll_seconds` or until stop
      - otherwise loads `messages_for` and `context_for`, awaits `handler.handle`, then `complete`, or `fail(str(exc))` on exception
    - **On stop during `handle`:** awaits the handler up to `lease_seconds / 2`; if it hasn't finished, cancels it and calls `release(job.id)`.
  - `RemService.recover_jobs()` (async wrapper of `IngestStore.recover`), called by the server at startup.

### Task 8: Daemon server and lifecycle

**Files:**
- Create: `src/rem/daemon/server.py`, `tests/test_server.py`
- Modify: `src/rem/cli.py` (adds a `daemon` subcommand → `run_daemon(load_config())`)

**Interfaces:**
- Consumes: everything above.
- Produces: `run_daemon(cfg: RemConfig, handler: JobHandler | None = None) -> int`. In order:
  1. **Config check.** Resolve `cfg.socket_path`; on `ValueError` → log it, return `3`.
  2. **Lock.** `InstanceLock(cfg.lock_path).acquire()`; on `AlreadyRunning` → log it, return `2`.
  3. **Stale socket.** If `socket_path` exists, unlink it. This is safe because we hold the lock.
  4. **Service.** Build `RemService(cfg)`; on `EmbedderMismatchError` / `EmbedderUnavailableError` / `StoreLockedError` → log it, release the lock, return `3`.
  5. **Recover.** `recover_jobs()`.
  6. **Serve.** Run uvicorn `Server(Config(build_app(svc), uds=str(socket_path), log_level="warning"))` and the `Worker` in the same event loop. `chmod(socket_path, 0o600)` once the socket exists (in the app's lifespan startup).
  7. **Signals.** SIGTERM/SIGINT set `server.should_exit` and the worker's stop event.
  8. **Shutdown.** Close the service, unlink the socket if it's still there, release the lock, return `0`.

  Logging uses the stdlib `logging` to stderr. Under `rem start`, stderr goes to `daemon.log`.
