# M7: Entities Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Facts are linked to the named things they are about (people, tools, projects, languages…). Entities are stored in `rem_entities__<slug>`, merged by normalized name, alias and similarity, linked to memories on both sides, and used to boost search.

**Architecture:** The existing extraction call is extended: each fact also lists the entities it mentions (name and type). No spaCy and no second LLM call. `entities.py` holds the pure rules (normalization, deterministic ids, merge decision). `Memory` owns every write: `apply_candidates` resolves and links entities after each memory is written, `delete` unlinks them, and `search` applies an entity boost. Entity ids are deterministic (`uuid5` of scope, project and normalized name), so replays never duplicate.

**Tech Stack:** Python 3.14, existing pydantic models, the existing `VectorStore` and embedder, pytest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-15-rem-design.md` (Graph-ready memory model: Entity payload and merge rule; Module boundaries: `entities.py`; M7 row; "Left to the builder": the entity extractor choice).

## Global Constraints

- No new runtime dependency (the spec leaves the extractor open; this plan picks the LLM already configured).
- Only `Memory` writes the stores. `retrieve` never writes.
- Entity merge: exact normalized name or alias match first, then cosine ≥ **0.95** against entities in the same bucket (spec: "~0.95"), then the new name is appended as an alias. The threshold is `ENTITY_MERGE_MIN`.
- Entity payload: `{id, name, normalized, type, aliases[], scope, project_id, memory_ids[], created_at, updated_at}` (spec).
- History: entity rows use `target_kind = entity`, events `ADD`, `MERGE` (alias added), `DELETE`.
- Entity ids: `uuid5(ENTITY_NS, f"{scope}|{project_id}|{normalized}")`. Replaying a job produces the same ids.
- Entities are scoped like memories: a `project` entity belongs to one project; `global` and `system` entities have `project_id = None`.
- Memory payload `entity_ids` already exists (M1); it is kept as a sorted, de-duplicated list.
- Entity names are limited to 80 characters and must be non-empty after stripping; invalid mentions are dropped, not errors.
- The extraction eval (`rem eval extraction`) is not extended in M7 (no entity labels in the dataset); see the ledger.

## Decisions taken in this plan (review these)

1. **Extractor:** the existing LLM call returns `entities: [{name, type}]` per fact (schema and prompt change). Reason: no spaCy model download, no second call, works with any configured provider. Cost: a larger output; quality depends on the model. Local `qwen3.5:4b` is the dev model.
2. **Scope buckets:** an entity exists once per (scope, project). "Python" mentioned in two projects gives two entities. Cost: no cross-project merge (M9 can show them linked).
3. **Search boost:** *(changed in the final review: `ENTITY_QUERY_MIN` is gone; bge-small scores 65% of unrelated query/name pairs ≥ 0.5)* an entity matches a query when its normalized name or an alias occurs in the normalized query as whole words (`entities.mentions_entity`); a memory linked to a matched entity gets `ENTITY_BOOST` (0.05) added to its hybrid score. Entities never create candidates, so an entity-only match cannot surface an unrelated memory.
4. **Deletion:** deleting a memory unlinks it from its entities; an entity left with no memories is deleted (`DELETE` history, target_kind entity).

## Review Focus

1. **Two projects, same name:** "Python" in project A and project B are two entities, each linked only to its own project's memories. Test in Task 4.
2. **Replay of a job:** running the same job twice leaves one entity per name, no duplicate `memory_ids` or `entity_ids`. Test in Task 4.
3. **Case and whitespace variants:** `"Python"`, `" python "` and `"PYTHON"` are one entity. Test in Task 2.
4. **Last memory deleted:** the entity goes; another memory still linked keeps it. Test in Task 5.
5. **Malformed LLM output:** an empty name, a name over 80 characters, or a missing `entities` key does not crash the job and does not drop the fact. Test in Task 3.
6. **Entity collection missing** (for example an M6 store opened for the first time): search still works without the boost. Test in Task 6.
7. **Reembed:** the entity collection is copied with the same ids and payloads and switched with the memories. Test in Task 7.

- Produces:
